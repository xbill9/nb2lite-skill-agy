# CLAUDE.md — NB2Lite Image Skill & nb2lite-agent MCP Agent

Guidance for Claude Code when working in this repository.

## Project Overview

This repository packages one Claude Code skill (`nb2lite-image`) and one **Model Context Protocol (MCP) server** (`nb2lite-agent`, a FastMCP app in `server.py`). Together they:

1. **Generate images:** text-to-image with `gemini-3.1-flash-lite-image` (NB2Lite) via the stateful Interactions API, with configurable aspect ratio and thinking level.
2. **Edit iteratively:** multi-turn stateful edits chained by interaction ID (`edit_image`) and inline base64 edits of local files (`edit_local_image`), with thread-safe local saving.

The tool surface is exactly four tools: `generate_image`, `edit_image`, `edit_local_image`, `get_help`. Public repo: [github.com/xbill9/nb2lite-skill-claude](https://github.com/xbill9/nb2lite-skill-claude), Apache-2.0 (`LICENSE` — keep it in sync with the license declared in `.claude-plugin/plugin.json`).

## Repository Layout & the Snapshot Sync Model

The repo-root files are authoritative; the skill is distributed as generated copies. **Edit the sources, then run `make skill` — never edit a snapshot directly.**

- **Sources (root):** `SKILL.md` (the skill manifest), `server.py` (the MCP server), `requirements.txt`, `mcp/project-setup.sh` (installer), `references/gemini-interactions-api.md` (vendored Interactions API guide — tracked in `skills-lock.json`, refresh from upstream rather than hand-editing).
- **Helper scripts (root):** `init.sh` — local bootstrap (deps + `.mcp.json` entry pointing at the root `server.py` + key setup; safe to rerun). `project-setup.sh` — thin wrapper that refreshes the `mcp/` snapshot then delegates to `mcp/project-setup.sh` (the real installer). `set_env.sh` — reads/prompts for the key (`~/gemini.key`), writes `.env`, and injects the key into `.mcp.json`; caution: it **replaces** the entry's whole `env` block with just the two key vars, dropping any custom `GEMINI_MODEL_NAME`/`IMAGE_OUTPUT_DIR`. `refresh_skill.py` — the snapshot sync run by `make skill`.
- **Generated by `make skill` (`refresh_skill.py`):**
  - `mcp/{server.py,requirements.txt}` — snapshots of the root sources (root copy is authoritative if they differ)
  - `.claude/skills/nb2lite-image/` — the assembled skill (active when working in this repo)
  - `skills/nb2lite-image/` — full copy of the skill in plugin layout (for the marketplace)
- **Generated, gitignored:** `.mcp.json` and `.env` (both embed the Gemini API key) — created by `./init.sh` on first run; `set_env.sh` injects the key. Never commit either or hand-edit them back into git. The key itself persists in `~/gemini.key`.
- **Plugin marketplace:** `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` make the repo installable via `/plugin marketplace add xbill9/nb2lite-skill-claude`. The plugin auto-registers the `nb2lite-agent` server (no key in the manifest — the server reads `GEMINI_API_KEY` from the environment). Validate changes with `claude plugin validate .`
- **Distribution zip:** `dist/nb2lite-image-skill.zip`, built by `make skill-package`; committed so the raw-GitHub-URL install works — rebuild it when the skill changes.

## Common Commands

```bash
./init.sh          # Local bootstrap: deps + .mcp.json (root server.py) + API key
make skill         # Refresh all skill snapshots + plugin copy from the root sources
make skill-install # Refresh + copy the skill to ~/.claude/skills (all projects)
make skill-package # Refresh + rebuild dist/nb2lite-image-skill.zip
make init TARGET=/path/to/project ARGS='--output-dir ./images'  # install skill + register MCP server
make test          # Agent integration tests (test_agent.py; needs a valid key)
make lint          # ruff check + format --check on the Python sources, bash -n on the scripts
claude plugin validate .   # check .claude-plugin manifests
```

The server's config comes from env vars: `GEMINI_API_KEY` (or `GOOGLE_API_KEY` fallback), `GEMINI_MODEL_NAME` (default `gemini-3.1-flash-lite-image`), `IMAGE_OUTPUT_DIR` (default `.`).

## Technical Standards: NB2Lite & the Interactions API

The Interactions API is Gemini's **stateful** endpoint: each call returns an `interaction_id` representing the turn's visual context persisted server-side, and passing `previous_interaction_id` lets the model edit the existing canvas while preserving character, style, lighting, and pixel continuity — no re-prompting the full scene. Full guide: `references/gemini-interactions-api.md` (and `GEMINI.md`).

### Request — `client.interactions.create(...)` (google-genai SDK)

| Parameter | Type | Notes |
| :--- | :--- | :--- |
| `model` | `str` | `"gemini-3.1-flash-lite-image"` (the server reads `GEMINI_MODEL_NAME`). |
| `input` | `str` \| `list` | Text prompt, or a list mixing `{"type": "image", "data": <b64>, "mime_type": ...}` and `{"type": "text", "text": ...}` parts for inline local-image edits. |
| `response_format` | `dict` | `{"type": "image"}`; optional `"aspect_ratio"`: `1:1`, `16:9`, `9:16`, `4:3`, `3:4`. Omit on stateful edits — the ratio is inherited from the previous turn. |
| `generation_config` | `dict` | `{"thinking_level": "low" \| "high"}` — the generic spec also lists `minimal`/`medium`, but the live API rejects them for this model (HTTP 400). |
| `previous_interaction_id` | `str` | Chain from the **latest** turn's ID — a stale ID silently forks the session from an older state. |
| `store` | `bool` | Must be `True` for any turn you may edit later; the MCP tools always set it. |

### Response — as consumed by `_handle_response` in `server.py`

- `interaction.id` — the new interaction ID to chain into the next edit (every turn returns a **new** one).
- `interaction.output_image` — may be absent (report the ID and the no-image note, don't crash); has `.mime_type` (png/webp, else jpg assumed) and `.data` (base64 `str` **or** raw bytes — handle both).
- Saved as `<prefix>_<unix-ts>_<uuid8>.<ext>` (`gen_`/`edit_`/`edit_local_`) under `IMAGE_OUTPUT_DIR`, created on demand; the UUID suffix keeps concurrent writes collision-free.

### Practices

- **Keep edit prompts incremental** — describe only the change ("make the sky dark blue with lightning"); the stored context holds the rest.
- **Don't change aspect ratio between stateful turns** — it degrades pixel continuity; pick it at generation time.
- **Thinking levels:** `low` (default) for fast previews and drafts, `high` for complex rendering, accurate text layout, or character composition; the spec's `minimal`/`medium` are rejected by the live API for this model. Generations are billable — batch related edits and use `low` when cost matters.
- **Tool errors return as `🔴 ...` text strings**, not protocol errors — check for them before reporting success.
- **Universal help:** the agent exposes a standardized `get_help` tool describing its active configuration environment variables and all exposed tools.

Upstream docs: [Interactions API Reference](https://ai.google.dev/api/interactions-api), [raw API details](https://ai.google.dev/api/interactions.md.txt).

## Coding Standards

- **No virtualenvs:** use the system `python3`; if dependencies are missing, warn with the `pip install -r requirements.txt` command instead of creating a venv (this is also how `mcp/project-setup.sh` behaves).
- **Dependency portability:** do not assume third-party libraries like `pandas` are installed. Prefer the standard library for data parsing and aggregation scripts.
- **Never commit secrets:** `.env`, `.mcp.json`, and `~/gemini.key` carry the API key and stay out of git.
